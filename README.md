# WAN DNS fixtures

Run an authoritative DNS test zone on a public server you control. The single
`compose.yaml` builds both images locally: BIND serves the configurable zone,
and a bounded front service exposes UDP and TCP port 53. Ordinary DNS answers
are available to public resolvers. Deliberate fault responses require an
explicit source-IP allowlist.

The package mirrors the existing public DNS test records at
`dns.quality-assurance.fyi`, then adds large A/AAAA/SRV sets, a roughly 60 KB
TXT reply, a reply near the 65,535-byte DNS-over-TCP limit, and controlled
transport faults. The companion client app's **Internet (custom)** option runs
132 cases against your delegated domain. The cases assess their listed RFC
requirements; they do not certify every DNS RFC.

## 1. Choose the delegated name and server

Use a dedicated subdomain, for example `wan.quality-assurance.fyi`. Keep your
existing Cloudflare zone and existing Internet fixtures in place. Prepare a
Linux server with a stable public IPv4 address and Docker Compose. Open inbound
**UDP 53 and TCP 53** in its host firewall and cloud security group.

Copy `.env.example` to `.env` and set:

| Variable | Meaning |
| --- | --- |
| `WAN_DOMAIN` | The exact delegated child zone, such as `wan.quality-assurance.fyi` |
| `WAN_NS1`, `WAN_NS2` | The nameservers named in both the child zone and parent delegation |
| `WAN_PUBLIC_IPV4_1`, `WAN_PUBLIC_IPV4_2` | Their public IPv4 addresses; the same address can be used for a temporary lab, but two independent servers are preferable for availability |
| `WAN_ZONE_SERIAL` | SOA serial; increase it whenever you change the zone data |
| `WAN_BIND_IPV4` | Local host interface on which to publish port 53, usually `0.0.0.0` |
| `WAN_ALLOWED_FAULT_CLIENTS` | Comma-separated client IPs/CIDRs allowed to trigger deliberately malformed or delayed responses; default permits loopback only |

`WAN_DNS_PORT` defaults to 53. Change it only for a local dry run: public DNS
delegation always reaches port 53. The `.env` file is ignored by Git.

Start the stack:

```sh
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

The Compose file builds from source. It does not depend on moving image tags
or a registry release. A named volume retains BIND's DNSSEC keys across
container restarts; preserve that volume when updating the package.

## 2. Delegate the zone from Cloudflare

In Cloudflare, open the **parent** zone (`quality-assurance.fyi` in this
example), then open **DNS → Records**. Create these records, all **DNS only**:

| Type | Name | Content |
| --- | --- | --- |
| A | `ns1.wan` | The value of `WAN_PUBLIC_IPV4_1` |
| A | `ns2.wan` | The value of `WAN_PUBLIC_IPV4_2` |
| NS | `wan` | `ns1.wan.quality-assurance.fyi` |
| NS | `wan` | `ns2.wan.quality-assurance.fyi` |

The A records are glue because these nameservers sit inside the delegated
child zone. The child zone generated by this package publishes matching
NS and A records. Set both the parent and child to the same real addresses.
Never create a CNAME for a nameserver. If nameservers are outside the child
zone, create their A records in the appropriate authoritative zone instead.

Cloudflare's [subdomain delegation guide](https://developers.cloudflare.com/dns/manage-dns-records/how-to/subdomains-outside-cloudflare/)
documents the parent NS records and in-child glue. Delegation is unavailable
for a Cloudflare domain using partial/CNAME setup.

Verify direct authority before waiting for recursive caches:

```sh
dig @YOUR_SERVER_IP wan.quality-assurance.fyi SOA +norecurse
dig @YOUR_SERVER_IP wan.quality-assurance.fyi NS +norecurse
dig @YOUR_SERVER_IP -t TXT +tcp 00000000000000000000000000000000.near-max.wan.quality-assurance.fyi +noall +stats
dig @YOUR_SERVER_IP -t TXT +tcp 00000000000000000000000000000000.max-tcp.wan.quality-assurance.fyi +noall +stats
```

Then test normal delegation from another network using your usual recursive
resolver and `dig +trace wan.quality-assurance.fyi SOA`. The 60 KB and 65 KB
checks need TCP; their UDP responses should be truncated and retryable.
Wire sizes vary with domain length, EDNS, additional data, and DNSSEC.

## 3. Publish a DS record for a validated DNSSEC chain

BIND signs the child zone and retains its key in `bind-cache`. After the
container is healthy, inspect the child DNSKEY and derive its DS:

```sh
dig @YOUR_SERVER_IP wan.quality-assurance.fyi DNSKEY +dnssec
docker compose exec authoritative sh -c 'for key in /var/cache/bind/keys/K*.key; do dnssec-dsfromkey -2 "$key"; done'
```

Add the **matching DS** for `wan` in the Cloudflare parent zone only after the
DNSKEY is visible on the public authoritative server. Check a validating
resolver afterwards with `dig wan.quality-assurance.fyi SOA +dnssec` and
`dig wan.quality-assurance.fyi DS +dnssec`. If DS publication is deferred,
the child is signed but has no validated chain from the parent; DNSSEC cases
remain observations and should be interpreted accordingly. Preserve the
key volume during upgrades or coordinate DS/key rollover.

## 4. Run the client tests

In the DNS client app, choose **Internet (custom)**, enter exactly the
`WAN_DOMAIN`, and run. It includes all 92 existing Internet cases against
your domain, all 38 existing transport cases that can use a WAN authority,
and two near-limit cases. Results retain the actual question, received bytes,
and selected resolver. The app uses the device's configured DNS path unless
you explicitly choose a resolver override.

Fault scenarios require the source IP seen by this server in
`WAN_ALLOWED_FAULT_CLIENTS`. Through a recursive resolver that may be the
resolver's egress IP rather than the laptop's IP. Start with one known test
source; expand only to trusted addresses. Unlisted sources receive REFUSED
for fault names. A DNS recursor may retry, cache, or sanitize malformed
responses, so use the raw response and the path recorded in the report when
assessing a fault case.

This suite uses documentation-range addresses as DNS data. They are not web
services. The WAN test server is authoritative only: recursion, zone transfers,
and updates are disabled. The normal cases remain publicly queryable.

## Local verification and provenance

Run `python3 -m unittest discover -s tests -v`. For a safe local Compose dry
run, set `WAN_BIND_IPV4=127.0.0.1` and `WAN_DNS_PORT=5303` before
`docker compose up -d --build`, then query `@127.0.0.1 -p 5303`.

The ordinary record template derives from
[`dns-server-lan-fixtures` revision ce82998c](https://github.com/johnneerdael/dns-server-lan-fixtures/tree/ce82998c35c798cc8c38228ddc9859a5247a03c2/external).
The generated zone, deployed image build, and actual DNS response are the
authoritative evidence for a particular installation. The current package
intentionally does not configure Cloudflare or deploy a public server for you.
